# 0003 · UI strings with `rust-i18n`, Spanish first

- **Status:** accepted
- **Date:** 2026-10-12
- **Deciders:** project owner, planning agents
- **Refs:** PDA-T-0008, PDA-T-0127, [`docs/research/bitacora-gpui.md`](../research/bitacora-gpui.md) §3.6

## Context

The planning notes proposed Fluent (`.ftl`). GPUI Kit itself uses `rust-i18n`, so a second
i18n library would mean two locale switches. Bitácora uses `rust-i18n 4.2` with YAML files
per namespace and forces English under `cfg!(test)` for stable snapshots.

## Decision

All user-facing copy lives in `crates/app/assets/locales/<ns>.<lang>.yml` and is read with
`rust-i18n` (`t!`). Spanish (`es`) is the source locale, English (`en`) the second. No UI
copy is hard-coded in Rust. Tests force one locale.

## Consequences

- One locale switch drives both our strings and GPUI Kit's components.
- No Fluent plural/gender rules; use explicit keys where Spanish needs them.

## Alternatives considered

| Option | Why not |
|---|---|
| Fluent (`fluent-rs`) | Second i18n system next to the kit's; no reuse from Bitácora |
| Hard-coded Spanish | Breaks the `en` locale and the repo language rule |
