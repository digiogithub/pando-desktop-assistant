# Spike S5 · Wake word comparison for "Oye Pando"

- **Task:** PDA-T-0022 (story PDA-US-0006) · **Date:** 2026-10-12 · **Author:** claude-opus
- **Code:** [`spikes/wake-word/`](../../spikes/wake-word/) (`prep_s5.py`, `s5_eval.py`) + the Whistle
  `bench` binary from [`spikes/whistle-ffi/`](../../spikes/whistle-ffi/)
- **Spec:** PDA-SP-0011.R1 (idle CPU < 3 % of one core), PDA-SP-0011.R3 (FAR < 1/h on 3 h,
  FRR < 10 % at 2 m) · **Related:** [S1](S1-whistle.md), `docs/research/voice-stack.md` §2, risk R14

## Options compared

| | Option | Runtime |
|---|---|---|
| **A** | Silero VAD v5 → first 2.0 s of each speech segment → Whistle (`language=es`, keyword bias `Pando / Oye Pando / Hey Pando`) → text match | sherpa-onnx VAD + libneedle |
| **B** | sherpa-onnx KWS, English GigaSpeech zipformer 3.3M (int8), keywords spelt with its BPE: `▁O Y E ▁PA ND O`, `▁O Y ▁PA ND O`, `▁HE Y ▁PA ND O` | sherpa-onnx |
| **C** | Custom openWakeWord-format model (`livekit-wakeword` / `oww-rs`) | not trained in this spike (see below) |

Match rules for A: **strict** = the word `pando` is one of the first two words of the
normalised transcript; **fuzzy** = a 1–2 word window in the first three words has
normalised Levenshtein similarity ≥ 0.8 to `oye pando`, `hey pando` or `pando`.

## Dataset (no microphone recording was possible for the agent)

All 16 kHz mono; generated by `prep_s5.py` into `~/.cache/pando-assistant-spikes/wake/` (not committed).

- **Negatives, 3.00 h:** MLS Spanish test audiobook speech (CC-BY-4.0, ≈ "podcast" condition),
  clips joined with 0.3–1.5 s gaps, mixed with synthetic office noise (pink noise + keyboard
  clicks) at 15 dB SNR. Contains no "Pando".
- **Positives, 162 clips:** 6 phrases ("Oye Pando.", "Oye Pando, ¿qué tareas hay pendientes?",
  "Oye Pando, cancela la migración.", "Hey Pando, abre Bitácora.", "Oye, Pando.", "Pando, para.")
  × 3 Piper voices (`es_ES-davefx`, `es_ES-sharvard`, `es_MX-ald`) × 3 speeds (0.85/1.0/1.2) ×
  3 **simulated** distances: 0.5 m (gain 1.0, RT60 0.25 s, 25 dB SNR), 1 m (0.5, 0.4 s, 15 dB),
  2 m (0.25, 0.6 s, 8 dB).
- **Confusers, 90 clips:** 10 near-miss phrases ("Oye, panda.", "Oye Pablo, ven.", "Pan de
  molde.", "Hoy pagando la cuenta.", "Oye, cuándo vienes." …) × 3 voices × 3 speeds at 1 m.
- **Idle:** 10 min of low-level pink noise (no speech).

## Results

Machine: Intel Core Ultra 9 285 (24 cores), shared with other agents' builds. CPU is process
CPU time (user + sys) divided by audio duration, so "1 %" = 1 % of one core.

### Accuracy

| Option | Positives detected (all, 162) | FRR @0.5 m / 1 m / 2 m ("Oye Pando" phrases only) | Confusers firing (90) | False accepts on 3 h negatives |
|---|---|---|---|---|
| **A strict**, with bias | 119 (73 %) | **3 % / 11 % / 25 %** | 12 (13 %) | **0** (0 /h) |
| A fuzzy, with bias | 123 (76 %) | 0 % / 11 % / 17 % | 21 (23 %) | 1 (0.33 /h) |
| A strict, **no** bias | 25 (15 %) | — (unusable) | 0 | 0 |
| B, thr 0.25 / score 1.0 (defaults) | 0 (0 %) | 100 % | 0 | 0 |
| B, thr 0.03 / score 5.0 (most permissive tried) | 3 (2 %) | ≈ 98 % | 0 | 3 (1.0 /h) |

"Oye Pando" phrases = phrases 1, 2, 3 and 5 (36 clips per distance). Per-phrase detail (A strict,
with bias): the bare "Pando, para." fails most (6/9, 2/9, 2/9 at 0.5/1/2 m) and "Hey Pando"
(English *hey* read by a Spanish voice) is weak (8/9, 4/9, 3/9). Confusers that fire: "Oye,
panda" 3/9, "Oye Pablo, ven" 4/9, "Pan de molde" 2/9. The keyword bias is what makes A work
(15 % → 73 % recall) and also what creates the confuser hits.

### CPU

| Option | Idle (no speech) | Continuous speech (3 h negatives) |
|---|---|---|
| A: VAD only | **0.20 %** | 0.24 % |
| A: Whistle passes (888 segments ≤ 2 s, 4 engine threads) | 0 % | 1.53 % (0.19 s CPU per pass) |
| **A total** | **0.20 %** | **≈ 1.8 %** |
| B: KWS | 0.9–1.6 % | 1.1–1.6 % |

Caveat: the audiobook stream produces one VAD segment every ~12 s. Dense conversation (one
segment every ~3 s) would cost ≈ 0.19 s / 3 s ≈ **6 %** of a core while people talk near the
mic, still ≈ 0.2 % when the room is quiet. Bound it in production: only verify segments that
start after ≥ 0.5 s of silence and last ≤ 2.5 s, rate-limit passes, and give the engine fewer
threads if the C API ever exposes it (the CLI has `--threads`, the C API does not).

### Option C (custom openWakeWord model): not measured

Training needs the `livekit-wakeword[train,eval,export]` Python stack (PyTorch, espeak-ng,
Piper/VoxCPM synthetic data — default English, so Spanish voices must be configured — plus
large negative feature sets) and tens of thousands of steps. That is a multi-hour job outside
this time-box and would also need the same real recordings to evaluate. Inference cost is
known to be low (≈ 200 KB classifier + shared mel/embedding models, pure-Rust ONNX in
`livekit-wakeword` 0.1.3; `oww-rs` 0.3.3 uses tract). Upstream openWakeWord *pretrained*
models are CC BY-NC-SA, so only a model we train ourselves is usable.

## Decision / recommendation for M9

1. **Option A (VAD → Whistle with keyword bias, strict match) is the v1 wake path.** It is the
   only option that understands Spanish: FAR 0 /h on 3 h, 3 % FRR at 0.5 m and 11 % at 1 m, idle CPU 0.2 %.
   It reuses the engine we already ship, so it costs no model and no new runtime.
2. **Option B (sherpa KWS with English tokens) is rejected** for "Oye Pando": 98–100 % FRR at any
   threshold, while burning about 1 % CPU all the time. The pipeline was checked against the
   model's own English test clips, which it detects correctly.
3. **Not yet meeting R3 at 2 m:** 17–25 % FRR on simulated 2 m audio at 8 dB SNR, against the
   10 % target. Before M9, in this order:
   - record the **real** fixture set required by R3 (3 h office/podcast + positives from ≥ 5
     speakers at 0.5/1/2 m on the reference laptop mic). The synthetic far-field model here
     is crude and may be pessimistic or optimistic;
   - tune on it: transcribe 2.5 s instead of 2.0 s, accept `pando` anywhere in the first
     three words when the word probability (`word_timestamps=1`) is high, keep the
     "Oye"/"Hey" prefix optional, and expose the sensitivity setting R3 asks for;
   - if FRR at 2 m is still > 10 % or dense-speech CPU > 3 %, train option C as a **first
     stage** in front of A (oWW gate → Whistle verification), which is what
     PDA-SP-0011.R2 already allows.
4. Recommend "Oye Pando" as the documented phrase. Bare "Pando" is too short (FRR 33–78 %),
   and "Hey Pando" depends on how a Spanish speaker pronounces *hey*.

## Reproduce

```bash
S=~/.cache/pando-assistant-spikes
$S/venv/bin/python -I spikes/wake-word/prep_s5.py $S 3
E="$S/venv/bin/python -I spikes/wake-word/s5_eval.py $S"
$E kws $S/wake/list_pos.tsv 0.25 1.0          # option B
$E vad $S/wake/negatives.wav neg              # option A, stage 1
target/spikes/release/bench $S/needle/whistle.cact $S/wake/list_seg_neg.tsv --lang es \
  --keywords $S/wake/kw_wake.txt > neg.jsonl  # option A, stage 2
$E scoreA neg.jsonl
```
