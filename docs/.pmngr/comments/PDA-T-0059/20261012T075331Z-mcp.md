cells/actions.rs + pane.rs: Cancel and Delete go through ui::confirm (which refuses to run without a Root), Relaunch = POST /orchestrator/tasks with the same prompt/engine/model/work_dir/tags. Approve/Deny never call Pando directly: they resolve the request in pando_client::approvals::Approvals with Decision::Approve/Deny and Origin::Explicit (flagged requests only allow that), then the outbox is delivered with permissions_respond; requests Pando stops listing are denied locally and never sent; a resolved request stays resolved when later polls still list it. 409 on cancel is classified as AlreadyFinished and shown as an info toast ("La tarea ya había terminado"), 404 as Gone; other errors as error toasts. Verified: unit tests (classify, relaunch body, pane ledger behaviour) and on xvfb (Aprobar sent {"action":"allow"} to the mock).
