Client side lives in pando-client `follow` module: `seen_for`, `should_attach`, `follow_session` -> `SessionFollow` (events ResetBubble / Chat / HistoryReload / RunFinished; `begin_local_run` + `observe` stop the poller attaching to the app's own run). Polls /pending every 4 s (configurable), claims run_seq before attaching, resets the bubble before every replay, reloads history when the replay had no content, reattaches while the run is active when a stream closes without done. G5 global stream does not exist yet: polling stays the path, the module doc names the swap point. Mock tests cover both PDA-SP-0002.R4 scenarios (resurrected run wakes mesnada; app restarted mid-run) plus reattach, empty replay and own-run suppression; a live #[ignore] test passed against a real pando serve (chat, then a follower with seen=0 receives the replay and finishes). Not done here: the UI side (bubble reset, notice rendering) belongs to the app crate.
