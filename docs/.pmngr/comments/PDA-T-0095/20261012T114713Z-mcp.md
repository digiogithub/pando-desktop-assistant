Profiled and fixed (commit perf(pando-stt) live.rs). Root cause: Needle stream_process re-reads all audio fed so far (0.75 s chunk: 25 ms at start, 800 ms after 13 s; stream_stop itself 0 ms), so the worker fell behind real time on long utterances and the release waited for the backlog. One-shot transcribe costs ~20 ms per second of audio. Fix: crates/pando-stt/src/live.rs LiveStream cuts the PTT stream at speech pauses (>=360 ms) or 4 s, decodes each finished phrase once while the user talks, and release decodes only the open phrase. Measured with crates/app/tests/ptt_latency.rs (release build, null-sink mic, key released at the end of the clip), release -> final Transcript: 2.7 s clip P50/P95 89/96 ms -> 35/48 ms; 13.6 s clip 1453/1551 ms -> 51/64 ms. Target <150 ms is met for the worker path including capture and IPC. The earlier 286-553 ms came from long utterances; the GPUI event pump after the worker's reply is not covered by this test (the app log 'voice turn' stats still need a re-check on a desktop session). Profiling tools: crates/pando-stt/examples/stream_latency.rs.
