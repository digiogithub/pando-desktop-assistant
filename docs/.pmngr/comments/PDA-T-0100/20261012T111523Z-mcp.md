Fix (commit f6e4866): `policy::tests::monotonic_in_confidence` failed. The cause was the property, not the policy. The shrunk counterexample had action `p = 1.5`. That value is invalid, so `p_of` fail-closes it to 0 and the outcome is LowConfidence. The test scaled the raw value to `1.5 × 0.55 = 0.83`, which is valid, so the "lowered" decision executed a reversible Status/All command. Scaling an untrusted value into the valid range is not a lowering. Treating invalid as 0 is the intended fail-closed behaviour (PDA-SP-0008.R2).

Change: the property now lowers the *effective* confidence (`p_of(..) * k`) of all five questions (intent, action, agent, engine, project), each with its own k (or unchanged). This makes it stronger than before. `policy()` is unchanged, and no fail-closed guarantee was relaxed. The regression seed `crates/decide/proptest-regressions/policy.txt` is committed.

Verified: `cargo test -p decide` passes 3×, a 50 000-case run of the policy proptests passes, and clippy `-D warnings` and fmt are clean.
