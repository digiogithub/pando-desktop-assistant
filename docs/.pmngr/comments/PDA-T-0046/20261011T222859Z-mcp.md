Implemented in pando-client: `auth` module (default_ca_path/load_local_ca; SecretStore trait with KeyringStore (feature keyring-store, service `pando-assistant`) and MemorySecretStore; CredentialPrompt hook = the single login dialog; AuthHooks) and recovery in `PandoClient::send`: 401 -> single-flight refetch of /api/v1/token and one retry; 401 `basic_auth_required` -> keychain, else prompt (one dialog per burst, stale keychain entry deleted before re-asking, saved after the prompt); credential headers are marked sensitive; the token is never persisted. If the token endpoint itself is unusable the original Unauthorized is returned. Tests: https with local rcgen CA (and failure without it); rotated token retried transparently; burst => exactly one refetch; persistent 401 not looped; Basic prompt once/remembered/cancelled/stale; separate binary installs a global tracing subscriber and asserts logs + Debug contain no token/password. Live #[ignore] test passed against a real `pando serve` (https + real CA, token fetched on first 401). Decision: keyring is default-on feature; Linux uses the pure-Rust zbus secret-service store.
