Spike S3 done on Linux x86_64; report `docs/spikes/S3-sherpa-onnx-single-runtime.md`, code `spikes/s3-sherpa-tts/`.

Results (Core Ultra 9 285):
- One static sherpa-onnx 1.13.8 runs Silero VAD v5 + Piper davefx + Kokoro v1_0 in one process: one ORT, 605 MB RSS.
- **First audio for a 10-word sentence, Piper davefx fp32: 132 ms warm with 2 threads (104 ms with 4), RTF 0.04. Meets < 300 ms.** Kokoro fp32 takes ~500 ms (260 ms if the first chunk is short). Kokoro int8 is slower: 1.1–1.3 s. int8 models are slower than fp32 on this CPU.
- Silero VAD costs ~53 µs per 32 ms window; onset is reported 150–175 ms late.
- Round-trip TTS→Whistle WER: Piper 20.5 %, Kokoro 15.9 %. Almost all errors are English loanwords ("auth", "pull request"), so text normalisation matters more than the choice of voice.
- **libneedle in the same binary: the naive link breaks C++ exceptions.** libc++abi's `__cxa_throw` and personality routine interpose libstdc++'s, so any ORT exception aborts the process. Fixed by making libneedle's libc++ symbol-private (`ld -r` + `objcopy`, recipe in the report). With that fix, STT and TTS run together and concurrently. The `nm` check to repeat on every target is in the report.
- A corrupt .onnx aborts the process even without libneedle: the worker must verify model SHA-256 before loading.
- Windows: sherpa's prebuilt static libs are MSVC and libneedle is GNU ABI, so they cannot share one binary.
- A VAD-only sherpa binary still contains espeak-ng (GPL). Feeds PDA-T-0023 / ADR 0007.
