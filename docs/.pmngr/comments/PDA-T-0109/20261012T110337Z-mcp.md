Verified on the real speakers/PipeWire (PulseAudio host): the monitor of the output sink records the tone at -26 dB (0.05 amplitude). Found and fixed: the PulseAudio backend asked for a 2 s buffer, so the first sound came 2 s late and 2 s of audio would keep playing after stop(); now a fixed 20 ms buffer (fallback to the default if refused): reported output latency 2000 ms -> 30-40 ms, stop->silent callback 26 ms -> 6 ms (ad0d01e). Alignment measured on a loopback (null sink): RMS rises +32 ms after play, the signal is audible on the loopback +89 ms, a 57 ms gap = reported latency 30 ms + capture buffering (ignored test `output_rms_is_aligned_with_the_audible_signal_on_a_loopback`). Closing.
