Spike S4 done on Linux/PipeWire; report `docs/spikes/S4-audio-cpal-rubato-sonora.md`, code `spikes/s4-audio-aec/`.

Results:
- cpal 0.18.2: the PipeWire/Pulse hosts are **opt-in features**. The pipewire feature needs libpipewire/libspa dev packages plus libclang. Duplex 48 kHz f32 with 1024-frame (21.3 ms) callbacks, 0 errors. Reported output latency is 42.7 ms. The Pulse host defaults to I24/I32 formats.
- rubato 5.0.1 `Fft` 48→16 kHz: flat passband, aliases at −105 dB or lower, 1.4 µs per 10 ms chunk, 5 ms delay.
- sonora 0.2.0 AEC3 at 16 kHz: 40 µs per 10 ms frame. **On a synthetic echo path (ERL 6–20 dB) over the real mic noise floor: ERLE 23–31 dB, 0 false barge-ins** with Silero VAD on the AEC output. Without AEC, the echo always triggers the VAD.
- Double talk: barge-in is detected about 320 ms after onset when the echo is ≥ 20 dB down. With a 10 dB echo it is suppressed until TTS ends, so hands-free barge-in needs a calibration gate, with PTT as the fallback.
- Hot-plug, simulated with a pactl null sink:
  - A stream on the default device follows default changes (`DeviceChanged`).
  - When an explicitly opened device disappears, **no error is raised**: the PipeWire host silently stalls, while Pulse re-routes.
  - A watchdog plus rebuild (8 ms) recovers. The PipeWire host snapshots its device list, so a new Host is needed to see new devices.
