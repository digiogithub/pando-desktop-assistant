Implemented in 758e2fd (crates/decide: questions.rs, state.rs, cascade.rs, text.rs). Sans-IO `Cascade` + `run` asks intent, then agent+action only for control, then engine+project only for spawn. State is a JSON-object string budgeted by model context (3 bytes/token, conservative) and 64 KiB; trims projects, then agents, then transcript.

Deviation (decision): the intent question uses 12 fine-grained classes (`stop_agent`, `agent_status`, …, `question`, `work_request`, `chat`, `dictate`) whose probabilities are summed per intent; `Decision.intent` is still `control|conversation|dictation`. With three abstract criteria tev1:0.8b scored 66/100 on the labelled set; with classes 77/80 on control+conversation. Dictation content is itself an instruction, so an explicit lead-in ("dicta", "escribe:", "apunta", "toma nota", "pon en el cuadro…") decides dictation by rule without a model call (bare "escribe …" is not a trigger).

Acceptance: `tests/live_intent.rs#intent_accuracy_above_90_percent` (#[ignore]) against local Ollama 0.35 + tev1:0.8b: **96/100**. Caveat: the fixture and the class descriptions were tuned together; a fresh held-out set would be a fairer measure.
